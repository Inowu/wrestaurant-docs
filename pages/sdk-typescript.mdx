El SDK oficial de W Restaurant para TypeScript y JavaScript es un cliente tipado
que cubre todos los endpoints de la API, con autocompletado y tipos de extremo a
extremo. Mantente al día actualizando el paquete con tu gestor de dependencias.

- **Paquete:** [`@wrestaurant/sdk`](https://www.npmjs.com/package/@wrestaurant/sdk)
- **Tipado:** TypeScript de extremo a extremo (también funciona en JavaScript puro)
- **Entornos:** Node.js, Deno, Bun y navegadores con `fetch`

## Instalación

```bash
npm install @wrestaurant/sdk
# o: pnpm add @wrestaurant/sdk
# o: yarn add @wrestaurant/sdk
```

## Configura el cliente

El cliente se autentica con tu **API key** (`wrst_live_…`), que se envía en la cabecera
`X-Api-Key` en cada solicitud. Consulta [Autenticación](/autenticacion) para obtener una.

```typescript
import { WrestaurantApiClient } from "@wrestaurant/sdk";

const client = new WrestaurantApiClient({
  apiKey: process.env.WRESTAURANT_API_KEY!, // wrst_live_...
});
```

> **Consejo:** nunca incrustes tu API key en código de cliente (navegador/app).
> Mantenla en el servidor o en variables de entorno.

## Organización del cliente

Los métodos están agrupados por recurso del Punto de Venta, con la forma
`client.<grupo>.<método>`. Por ejemplo, `client.productos.getProducts` o
`client.turnos.openShift`. Cada grupo corresponde a una sección de la
[Referencia API](/api).

## Tu primera llamada

Cada endpoint recibe la **license key** de la sucursal (16 caracteres, p. ej.
`DS5D2368HCME4O9X`). Consulta [Sucursales](/workers) para entender las license keys.

```typescript
const productos = await client.productos.getProducts({
  licenseKey: "DS5D2368HCME4O9X",
  page: 1,
  pageSize: 100,
});

console.log(productos.totalResults, productos.products);
```

## Paginación

Los endpoints de listado devuelven `page`, `pageSize`, `totalPages` y `hasNextPage`.
Itera hasta agotar las páginas:

```typescript
let page = 1;
const all = [];

while (true) {
  const res = await client.productos.getProducts({
    licenseKey: "DS5D2368HCME4O9X",
    page,
    pageSize: 100,
  });
  all.push(...(res.products ?? []));
  if (!res.hasNextPage) break;
  page++;
}
```

## Crear una orden

Las órdenes abiertas (cuentas en curso) viven en `client.ordenes`. Las órdenes ya
cerradas (cheques) se consultan con `client.cheques`.

```typescript
const orden = await client.ordenes.createTempOrders({
  licenseKey: "DS5D2368HCME4O9X",
  mesa: "12",
  noPersonas: 2,
  productos: [
    { idProducto: "P001", cantidad: 2 },
  ],
});

console.log(orden.folio);
```

## Manejo de errores

Las respuestas con error (401, 404, 429, …) lanzan una excepción tipada
`WrestaurantApiError` con el código de estado y el cuerpo de la respuesta.

```typescript
import { WrestaurantApiClient, WrestaurantApiError } from "@wrestaurant/sdk";

try {
  await client.productos.getProducts({ licenseKey: "DS5D2368HCME4O9X" });
} catch (err) {
  if (err instanceof WrestaurantApiError) {
    console.error(err.statusCode, err.body); // p. ej. 429 -> límite excedido
  } else {
    throw err;
  }
}
```

Consulta [Límites de uso](/limites) y [Errores](/errores) para los códigos y cabeceras
de control de tasa.

## Métodos disponibles

Cada endpoint de la API tiene su método equivalente dentro de su grupo. Todos los
métodos reciben un solo objeto con los parámetros de ruta (como `licenseKey`), los de
consulta y los campos del cuerpo. La lista completa, con todos los parámetros y tipos de
respuesta, está en la [Referencia API](/api). Cada endpoint incluye el ejemplo listo
para copiar con el SDK.

| Grupo | Métodos |
| --- | --- |
| `client.productos` | `getProducts`, `updateProduct`, `getBestSellers` |
| `client.grupos` | `getGrupos`, `getSubgrupos` |
| `client.estaciones` | `getStations` |
| `client.mesas` | `getMesas` |
| `client.meseros` | `getMeseros`, `authenticateMesero` |
| `client.clientes` | `getClientes` |
| `client.empresas` | `getEmpresas` |
| `client.turnos` | `getTurnos`, `openShift`, `closeShift` |
| `client.asistencias` | `getAsistencias` |
| `client.formasDePago` | `getPaymentMethods` |
| `client.tiposDescuento` | `getTiposDescuento` |
| `client.ordenes` | `createTempOrders`, `getTempOrders`, `getOpenOrders`, `getTempOrderDetails`, `addOrderItems`, `cancelOrderItems`, `applyOrderDiscount`, `applyItemDiscounts`, `renameOrder`, `assignOrderClient`, `printOpenOrder`, `closeOpenOrder`, `createClosedTempOrder` |
| `client.cheques` | `getOrders`, `searchOrders`, `getOrderDetails`, `getDayOrders` |
| `client.facturas` | `getFacturaXml` |
| `client.impresoras` | `listPrinters`, `getPrinter`, `createPrinter`, `updatePrinter`, `deletePrinter`, `getPrinters`, `printOrder`, `printTest` |
| `client.puntosDeVenta` | `getTicketHeader`, `updateTicketHeader` |

## Migrar desde la versión 0.x

A partir de la versión **1.0.0**, los métodos que estaban en `client.endpoints` se
movieron a su grupo. Los nombres de los métodos no cambian, solo el grupo:

```typescript
// 0.x
await client.endpoints.getTurnos({ licenseKey: "DS5D2368HCME4O9X" });

// 1.0.0 o superior
await client.turnos.getTurnos({ licenseKey: "DS5D2368HCME4O9X" });
```

Los métodos de `client.impresoras` no cambian.
